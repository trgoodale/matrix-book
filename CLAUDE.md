# Notes for Claude: Matrices in Practice

Working notes for Claude sessions on this book: how it is put together, decisions
already made (so they are not reopened or undone), and when each check was last
run. Read this before starting work, and update it when a decision is made or a
check is run. The README covers how to write chapters (chapter pattern, notation
macros, code tabs, cross-references, app embeds, accessibility rules); this file
does not repeat it.

Author: Tom Goodale. Repository: github.com/trgoodale/matrix-book (public, branch
`main`). Site: https://trgoodale.github.io/matrix-book/. Tom's working copy is in
OneDrive on Windows, so files there have CRLF line endings.

## Structure

- **Front matter** (`index.qmd`, `front/`): welcome; *How to use this book* (levels,
  reading routes, running the code); *Notation and conventions* (the Notation button,
  the bold/italic rule, figure labels); *Refresher* (including a code primer,
  `#sec-code-primer`).
- **Six parts, 42 chapters**, each Part ending in an unnumbered review page:
  I Matrices and transformations (1–9), II Linear systems (10–13), III Vector spaces
  (14–17), IV Eigenvalues and matrix calculus (18–23), V Numerical methods (24–30),
  VI Applications (31–42). Parts I–V use the full chapter pattern; Part VI the
  shorter application pattern (see README).
- **Appendices** (lettered A–K in order): A Interactive apps (`apps.qmd`), B Reference,
  C Proofs, D Matrix calculus identities, E–J Solutions Part I–VI, K Glossary.
- **Glossary** (`appendices/glossary.qmd`): about 320 entries under A–Z letter
  headings (`#glossary-x`), with a compact A–Z jump row at the top (`.glossary-az`;
  X and Y have no entries and are shown greyed, hidden from screen readers). Add a
  glossary entry when a chapter formally defines a new term.
- **Apps** (`apps/`, 27 self-contained HTML files), embedded with `?embed=1`. Most take
  start-up settings in the link (`?preset=<button name>`, `?m=` for a matrix); worked
  examples link to the app opened at the matching preset.
- **Code files** (`code/`): a notebook and a MATLAB script per chapter, per Part review
  and per Part's solutions, generated by `tools/make_code_files.py` (README explains).
- **Workflows**: `publish.yml` (build and deploy on push to `main`; regenerates code
  files and publishes notebooks with outputs), `check-code.yml` (code/ up to date,
  every notebook and MATLAB script runs; on push, PR and Mondays).

## Decisions already made

Book content and style
- Levels: chapters carry a Core or Further badge. Chapters 40 and 41 stay Core, each
  with a "What you need from Chapter 20" box (40's also covers Chapter 23).
- No "first year" / "second year" wording anywhere: institutions differ. The
  engineering route is called "Engineering mathematics"; Core is described as
  "introductory university courses".
- Reading routes in *How to use this book*: Engineering mathematics, Computing and
  computer science, Physics, Biology and life sciences, Statistics and data science,
  Economics and business, Numerical methods (a second course; it says what it
  assumes). Every route must include each chapter's Builds on chapters; recheck
  routes when a Builds on line changes.
- Worked examples sit straight after the subsection they practise, in every Part
  including VI. Example ids are `#ex-<chapter key>-<n>`.
- Bold marks only formally defined new terms and labels (paragraph labels, app
  button/preset names, "Solution."); italic marks emphasis. Part VI chapters keep bold
  on their own definitions because readers may start there.
- "Watch out" boxes (warning callout style) mark classic errors: currently in
  Chapters 2, 3, 6, 7, 18, 23, 24 and 35.
- † marks harder exercises (about 1 in 6; none in Chapters 1, 2, 11, code exercises
  or reviews); screen readers hear "Harder exercise".
- Core proof exercises have one-line hints, checked against the worked solutions.
- Each Part review revisits earlier Parts and includes one code exercise.
- Labels inside diagrams always use the default bold notation (stated on the
  conventions page); the text and captions follow the reader's notation setting.

Code and publishing
- Python and MATLAB in tabs throughout. Python runs at build time; MATLAB output is
  pasted. A few MATLAB-only functions are used (`decomposition`, `max(...,'all')`,
  `eigs(...,'smallestabs')`), so *How to use* says "almost all" MATLAB code runs in
  Octave. Chapter 28 uses `fsolve` (Optimization Toolbox, installed in CI).
- Notebooks in the repository have no outputs (Colab opens them from `main`); the
  website's copies are run at publish time and include outputs. Tom chose to keep this
  setup rather than point Colab at `gh-pages`.
- `_freeze` is committed and stays committed; CI re-runs any changed chapter, so a
  local render before each commit is not required for the site. A local render is
  needed only to regenerate `code/` after changing chapter code or code exercises.
- Eight solutions are given in Python only; their MATLAB versions are in
  `tools/matlab_solutions/`.

Accessibility
- Target: WCAG 2.2 AA. Apps never rely on dragging alone: single points move to a click,
  several points have a **Move:** selector (vector mixer, basis grids, vector explorer),
  3D views have **Turn** buttons (span explorer, linear systems, determinant explorer).
  The arrow keys move whatever the Move selector picks.
- `assets/components.scss` enlarges Quarto's small controls to 24 px, lets
  cross-reference links wrap on narrow screens, and lets long reference URLs break.
- MathJax 4 provides speech and braille for every formula. Every formula is also a Tab
  stop (MathJax default `inTabOrder: true`): an open question for Tom (see Ideas).
- Animated apps only move after Play; eight of them (heat plate, iteration race, matrix
  powers, normal modes, power method, random surfer, robot arm, row reduction) do not
  check prefers-reduced-motion (AAA only, since motion is user-started); phase portrait does.

## Working practices (for Claude)

- Tom edits from the OneDrive folder; Claude's copy is a working copy. Before saving
  back: stage the device files and check they still match the last saved version
  (ignoring CR), then write with CRLF endings. Files in `.github/workflows/` are
  protected from remote writes: send them to Tom to put in place.
- Ask before large or irreversible changes; otherwise get on with it.
- A full `quarto render` takes 10–25 minutes in Claude's sandbox; run it in the
  background. SCSS changes need a full render.
- Testing in Claude's sandbox: the MathJax CDN is blocked, so serve the local copy
  (`/tmp/mj/node_modules/mathjax`, version 4.0.0) by intercepting requests; otherwise
  pages are tested without maths. Scripts used in the 2026-11-21 audit (full-site axe
  with WCAG 2.2 rules and dark-mode check, app keyboard walk, app function tests) were in
  the session scratchpad and are not kept; rewrite them from this description if needed.
- Earlier review document (pedagogy and cognitive load review, with every item marked
  Done): https://claude.ai/artifact/VV11gzreAUby5fKDW4C1a2
